# Patterns

Patterns are **composed page layouts** — combinations of primitives wired
together with state and copy. Drop one in to ship a screen in minutes;
fork it for anything non-trivial.

## Available patterns

| Pattern | What | Best for |
|---|---|---|
| `AuthLayout` + `SignInForm` / `SignUpForm` / `ForgotPasswordForm` / `MagicLinkSent` | Auth screen wrapper + 4 form variants | Sign-in flow |
| `AppShell` + `Dashboard` | Sidebar + topbar + 4 stat cards + chart + activity table | Authenticated home |
| `SettingsPage` | Sub-nav + 5 sections (profile, security, notifications, billing, team) | Account settings |
| `DataTablePage` | Filters + search + bulk action bar + grid + pagination | List / index pages |
| `RecordDetail` | Breadcrumbs + header + tabs + side panel | Item detail pages |
| `Onboarding` | 4-step stepper flow | Post-signup wizard |
| `Pricing` | 3-tier comparison | Marketing pricing |
| `FirstRunEmpty` | Hero + 3 next-step cards | Brand-new account |

## Using a pattern

Patterns are exported alongside primitives:

```tsx
import { AppShell, Dashboard } from '@craftzbay/ui';

export default function HomePage() {
  return (
    <AppShell brand={<MyLogo />}>
      <Dashboard />
    </AppShell>
  );
}
```

## AppShell — the most-used pattern

`AppShell` ships responsive out of the box:

- **Desktop:** Sidebar (collapsible) + slim topbar with search / notifications / profile dropdown.
- **Mobile:** Sidebar collapses into a hamburger Sheet — topbar shows the brand and dropdowns.
- **Sidebar header / footer:** brand goes in `header`; user card / footer goes in `footer`.

```tsx
<AppShell brand={<MyLogo />} active="projects">
  <YourPageContent />
</AppShell>
```

The `active` prop highlights the matching sidebar item. Hash navigation
(`#dashboard`, `#settings`, `#data-table` …) is wired in by default in the
showcase — your real app will replace those `href`s with your router's links.

## When to NOT use a pattern

- The pattern is opinionated about copy, structure, and density. If your
  product needs a fundamentally different IA, fork the pattern (just copy
  the source file into your app) and iterate.
- Patterns are **demo-grade complete**, not feature-complete. They show the
  intended skeleton — you wire up real data, routing, and validation.

## Customising

Every pattern composes primitives. Open the source to see how — then either:
1. Pass props through (the `brand` slot, `active` key, `onSubmit` callbacks).
2. Fork the file into your codebase and modify directly.

Both are first-class. The patterns exist to save you typing, not to lock
you in.
